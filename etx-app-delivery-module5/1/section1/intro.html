Modernizing Applications with Migration Toolkit for Applications

The Challenge

Many organizations rely on large portfolios of applications built on traditional application servers and legacy frameworks.

While these applications continue to provide business value, they often become increasingly difficult to maintain, secure, and deploy on modern cloud-native platforms such as Red Hat OpenShift.

Figure 1. Modernizing Existing Applications (Click the image to view it in full size in a new browser tab)

Development teams are frequently faced with questions such as:

  • Which applications should be modernized first?

  • How much effort will each migration require?

  • Which technologies are no longer supported?

  • What code changes are needed before moving to OpenShift?

  • Can modernization happen without rewriting the entire application?

Instead of manually reviewing thousands of source files, organizations need an automated way to assess existing applications and plan modernization efforts.

Modernization does not always mean rewriting an application.

Many organizations achieve significant value by incrementally modernizing existing applications while preserving their existing business logic.

What is Migration Toolkit for Applications?

Migration Toolkit for Applications (MTA) helps organizations assess, plan, and modernize existing applications for modern runtimes and cloud-native platforms.

Rather than manually reviewing application source code, MTA analyzes the application, identifies migration issues, estimates modernization effort, and generates detailed reports that guide developers through the modernization process.

This enables modernization projects to become predictable, repeatable, and easier to manage across large application portfolios.

How MTA Helps Modernize Applications

MTA provides several capabilities that simplify application modernization.

Capability Purpose

Application Analysis

Scans application source code, configuration files, and dependencies to identify migration issues.

Migration Rules

Uses pre-built rule sets to detect changes required for different runtimes, frameworks, and migration targets.

Portfolio Assessment

Analyzes multiple applications to help prioritize modernization efforts across large application portfolios.

Web Console

Provides a centralized interface for managing modernization projects and reviewing migration reports.

CLI

Enables automated application analysis from developer workstations and CI/CD pipelines.

Modernization Strategies

Not every application requires the same modernization approach.

Organizations typically adopt one of the following strategies depending on business requirements.

Strategy Description

Rehost

Move the application to new infrastructure with little or no code changes.

Replatform

Containerize the application and move it to OpenShift while making minimal application changes.

Refactor

Redesign the application to adopt cloud-native architectures such as microservices or modern Java frameworks like Quarkus.

Supported Modernization Targets

After modernization, applications typically run on one of Red Hat’s supported runtimes.

Runtime Typical Use Case

Red Hat build of Quarkus

Modern Kubernetes-native Java applications with fast startup and low memory consumption.

JBoss Enterprise Application Platform (EAP)

Enterprise Jakarta EE applications requiring long-term support.

Red Hat build of Spring Boot

Modern Spring Boot applications with enterprise support.

Node.js, .NET, and Go

Modernize applications across polyglot development environments.

MTA in the Software Factory

Application modernization becomes another workflow within the Software Factory.

Instead of starting with a new application, developers begin with an existing application and use MTA to prepare it for modern platforms.

A typical modernization workflow includes:

  1. Analyze the existing application using MTA.

  2. Review migration reports and recommended changes.

  3. Modernize the application to use a supported runtime.

  4. Commit the updated application to Git.

  5. Validate changes through the CI pipeline.

  6. Deploy the application using GitOps.

  7. Continue operating the application using the same Software Factory processes.

This allows organizations to modernize existing applications while continuing to use the same standardized development, security, and deployment workflows.

Migration Toolkit for Applications does not automatically rewrite applications.

Instead, it analyzes existing applications, identifies migration issues, and provides actionable guidance that helps development teams modernize applications efficiently.

This enables development teams to migrate applications to modern platforms while continuing to use the same standardized Software Factory for building, testing, deploying, and operating software.
